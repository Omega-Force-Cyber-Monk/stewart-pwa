## 5. Implement trigger and eligibility controller

### `useExitIntentPopup.ts`

1. Determine eligibility from the current pathname and `resolveBusinessHost`:
   - main host only;
   - exactly `/`, `/senior`, `/women`, `/couple`, `/spanish`;
   - both anonymous and authenticated visitors;
   - never tenant, dashboard, admin, auth, payment, or any other route.
2. On eligible entry:
   - create/reuse `quittheapp:marketingSessionId`;
   - overwrite last-touch attribution, including empty values;
   - reset route-local trigger listeners/timer only; do not reset the global consumed-session marker.
3. Desktop classification:
   - use `window.matchMedia("(pointer: coarse)").matches`;
   - when false, listen only for `mouseleave` with `clientY <= 0`;
   - do not claim to detect browser chrome/tab-bar movement.
4. Mobile classification:
   - when coarse pointer is true, start a 30-second timer on eligible entry;
   - attach an `IntersectionObserver` to a deterministic hero element marked with `data-exit-intent-hero`;
   - at the timer check, show only if the latest hero intersection ratio is greater than zero;
   - if the hero is not visible at that check, do not show during that visit.
5. Before showing, check:
   - one-popup-per-session state;
   - Spanish lead-config state when route is `/spanish`;
   - shared pricing/abandoned overlay state.
6. Mark the global session as consumed as soon as the popup is shown.
7. Clean up mouse listeners, timer, observer, route subscriptions, and overlay subscriptions on unmount/route change.
8. Keep FAQ sections untouched. No suppression event will be generated because the five FAQs remain static.
