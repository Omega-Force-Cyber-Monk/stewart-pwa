# Stewart PWA — Production Deployment Guide (Frontend)

**App:** `stewart-pwa` (React 19 + Vite + RTK Query PWA)
**Hosting:** AWS S3 + CloudFront (static) · **API:** see `stewart-backend/DEPLOYMENT.md`
**DNS:** GoDaddy

---

## 1. What this app is

A static React SPA + PWA. It talks to the backend API over HTTPS. There is **no server** for this app — everything is pre-built to static files in `dist/` and served by CloudFront.

The same build serves **two kinds of pages**:
- The main app: `https://app.yourdomain.com` (auth, rider dashboard, admin dashboard)
- Every rider's personalized website: `https://<slug>.yourdomain.com` (public booking pages)

Both are the same SPA — the slug in the URL picks which business renders (via the public API).

---

## 2. Build

### 2.1 Set the API base URL (build-time)

Create `.env.production` in the repo root:

```env
VITE_API_BASE_URL=https://api.yourdomain.com/api/v1
```

> ⚠️ `VITE_*` vars are baked into the bundle at **build time**. If the URL changes you must rebuild. The default fallback is `http://localhost:3000/api/v1` — useless in prod, so this file is mandatory.

### 2.2 Build

```bash
npm ci
npm run build        # → dist/
```

Build outputs (from `vite.config.ts`): hashed JS/CSS, images, `sw.js` (Workbox service worker), `manifest.webmanifest`, icons.

---

## 3. S3 bucket

1. Create bucket `stewart-pwa-prod` in **us-east-1**.
2. **Block all public access** (CloudFront uses Origin Access Control, not public reads).
3. Bucket policy — not needed for OAC; the CloudFront distribution gets access via OAC.

Upload:
```bash
aws s3 sync dist/ s3://stewart-pwa-prod --delete
```

## 4. CloudFront distribution

| Setting | Value |
|---|---|
| Origin | S3 `stewart-pwa-prod` with **Origin Access Control (OAC)** |
| Origin domain | `<bucket>.s3.us-east-1.amazonaws.com` |
| Default root object | `index.html` |
| Viewer protocol | `Redirect HTTP to HTTPS` |
| Alternate domain (CNAME) | `app.yourdomain.com` **and** `*.yourdomain.com` |
| SSL cert | ACM wildcard `*.yourdomain.com` (must include `yourdomain.com` + `app.yourdomain.com`), us-east-1 |
| Price class | whatever fits budget (All Edge Locations recommended) |

### 4.1 SPA routing (critical)
React Router needs server-side fallback to `index.html` for client routes like `/dashboard`, `/admin`, `/payment/success`:

- **Error responses:** create custom error responses:
  - 403 → `/index.html` with response code **200**
  - 404 → `/index.html` with response code **200**

### 4.2 Caching
- Default cache policy for hashed assets (JS/CSS/images): long cache (1y) — safe because filenames are content-hashed.
- `index.html`: **No-Cache / must-revalidate** — otherwise new deploys never appear.

### 4.3 PWA service worker
- `sw.js` is generated by `vite-plugin-pwa` (Workbox).
- It precaches hashed assets and caches images (CacheFirst) + same-origin app shell (StaleWhileRevalidate). API calls are **excluded** (`!url.pathname.startsWith("/api")`) — never cache API responses.
- After every deploy, run a CloudFront invalidation so `sw.js` + `index.html` update:
  ```bash
  aws cloudfront create-invalidation --distribution-id <ID> --paths "/*"
  ```

## 5. DNS (GoDaddy)

| Type | Name | Value | Purpose |
|---|---|---|---|
| CNAME | `app` | `<distribution>.cloudfront.net` | Main app |
| CNAME | `*` | `<distribution>.cloudfront.net` | **Rider personalized websites** (`<slug>.yourdomain.com`) |
| CNAME | `api` | backend endpoint (ALB/EC2) | API — see backend guide |

> The wildcard `*` is what makes `https://johns-rides.yourdomain.com` work. It must point to CloudFront, and CloudFront must have the wildcard cert.

## 7. Common Q&A

**Q: Why does the app call `localhost:3000` in production?**
A: `.env.production` is missing or `VITE_API_BASE_URL` is unset → falls back to the dev default. Rebuild with the correct URL.

**Q: Rider website `<slug>.yourdomain.com` shows the main app or errors.**
A: (1) Wildcard CNAME + wildcard ACM cert. (2) The business must be **ACTIVE** — the public API returns 404 for non-active businesses and the app shows "Website not found". (3) `PUBLIC_BUSINESS_DOMAIN=yourdomain.com` on the backend.

**Q: After deploy, users still see the old version.**
A: `index.html` caching or the service worker. Ensure `index.html` is No-Cache and run the CloudFront invalidation. The service worker updates in the background on next load (Workbox `registerType: "prompt"` — users may need to refresh once).

**Q: Which env vars does the frontend need?**
A: Only `VITE_API_BASE_URL` (build-time). Everything else (Stripe, DB, etc.) lives on the backend.

**Q: Can I host the frontend on EC2/Nginx instead?**
A: Yes — upload `dist/` to `/var/www/html`, serve with Nginx, and add `try_files $uri /index.html;` for SPA routing + a wildcard server block with the wildcard cert. S3+CloudFront is preferred (cheaper, CDN, managed TLS).

**Q: The PWA won't install / offline mode broken.**
A: Service worker requires HTTPS (CloudFront gives you that) and the `manifest.webmanifest` + icons must be served. Check DevTools → Application → Service Workers. If `sw.js` is cached by CloudFront, invalidate.

**Q: Payment success page shows "Confirming your payment…" forever.**
A: The page polls `/auth/me` for `purchase.status === "paid"`, which only flips when the **Stripe webhook** hits the backend. Check: backend webhook endpoint + secret, and that the payment was actually completed. Not a frontend issue.

## 8. Suggested CI/CD (GitHub Actions)

```yaml
# .github/workflows/deploy.yml
name: Deploy frontend
on:
  push:
    branches: [main]
    paths: ['src/**', 'package.json', 'vite.config.ts']
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 24 }
      - run: npm ci
      - run: echo "VITE_API_BASE_URL=${{ secrets.VITE_API_BASE_URL }}" > .env.production
      - run: npm run build
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: us-east-1
      - run: aws s3 sync dist/ s3://stewart-pwa-prod --delete
      - run: aws cloudfront create-invalidation --distribution-id ${{ secrets.CLOUDFRONT_DIST_ID }} --paths "/*"
```
